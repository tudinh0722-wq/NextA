## 3. Current implementation

### Flutter planner
The current planner already has:
- month-first calendar hierarchy;
- month/week collapse and expansion;
- directional month navigation;
- week navigation by whole weeks;
- selected-day agenda;
- event create/edit/delete/search;
- SQLite persistence;
- Material 3 theming;
- minute-aligned countdown refresh;
- countdown formatting with hour precision for multi-day durations;
- Samsung Calendar-inspired Add Event editor;
- priority selection and persistence;
- reminder configuration and repeat metadata;
- finite recurrence generation and recurrence UI;
- calendar quick tap and long press behavior;
- non-interactive empty agenda state;
- AI Import placeholder reserved for the bulk-import workflow.

### Event data
`NextAEvent` is a concrete dated occurrence.

Recurring occurrences:
- share `recurrenceId`;
- carry recurrence metadata on concrete occurrences;
- are generated by the pure recurrence policy before persistence;
- are finite by count or end date, with a hard safety cap.

SQLite (`nexta.db`) is the Flutter source of truth.

### Priority
The shared event priority palette is:
- normal: pastel blue;
- important: pastel orange;
- very important: pastel red.

The same persisted priority must drive:
- event editor priority dot;
- agenda countdown outline;
- calendar event markers/background tint.

## 4. Current UI contract

### Locked screens — Calendar and Agenda

**These two screens are complete and form a frozen UI baseline.** Their visual presentation must not be changed, redesigned, resized, restyled, or structurally refactored unless the user explicitly requests a change.

Functional bug fixes are allowed when necessary, but must preserve the established appearance and interaction contract unless the user explicitly asks otherwise.

#### Calendar
- Calendar event markers are limited to two bars per day.
- Bars are stacked **vertically** on the Y axis.
- Every marker bar has the same width.
- Priority changes marker color only; it does not change marker geometry or inset.
- Quick tap selects/navigates to the day.
- Long press opens Add Event with that exact day preselected.

#### Agenda
- Start/end time is visually prominent and centered.
- Start/end time and countdown occupy the standardized right-side time block.
- Countdown surface uses the same width as the start/end time block.
- Countdown label and value are centered.
- Empty `Không có sự kiện` state is informational and non-interactive.

**Locked-screen rule:** Do not use future cleanup, responsive work, design-system consolidation, or refactoring as a reason to alter these screens. Preserve the current baseline exactly unless the user explicitly reopens the design.

### Add Event
Current hierarchy:
1. compact `Thêm sự kiện | AI Import` header;
2. title + compact priority dot;
3. start/end date-time columns;
4. `Địa chỉ`;
5. `Ghi chú`;
6. reminder configuration;
7. reminder repeat;
8. recurrence;
9. floating `Thoát | Lưu` action pill.

Rules:
- title max 47 characters;
- address max 30 characters;
- note max 30 characters;
- no All-day control;
- no separate priority row;
- priority selector expands horizontally at the title dot;
- date/time text is tappable without calendar/clock icons;
- recurrence uses a centered radio dialog;
- recurring frequency expands an indented finite end section;
- default recurrence count is 10;
- reminder default is 10 minutes before;
- default repeat is 2 additional reminders at 5-minute intervals;
- disabled reminder persists as `reminderMinutes = 0`.

## 6. Platform surfaces

NextA has separate presentation responsibilities:

1. **App Screen** — detailed planner/navigation.
2. **Home Widget** — glanceable Today Schedule using Android `RemoteViews`.
3. **Focus/Lock Screen** — Now & Next with large countdown where the host platform permits it.
4. **Notification fallback** — used where a dedicated Lock Screen surface is unavailable.

These surfaces share semantics but should not be forced into one UI implementation.
